# 指導計画ファイル（.sdkk）作成プロンプト

「ことばのわざ概念ツリー」で読み込む指導計画ファイル（.sdkk）を、教科書会社の年間指導計画などの資料から、生成AI（Claude など、ファイルを読んでスクリプトを実行できるもの）に作らせるためのプロンプトです。

## 役割の分け方

| もの | 持つもの・すること |
|---|---|
| 指導計画ファイル（.sdkk） | 単元ごとのパラメータ：時期・時数・指導事項（◎○）・言語活動例（☆）・文種・構成の型・展開の型・資料の記述に基づくひも付け。教師が作り、アプリで直す。 |
| アプリ本体のデータ | わざの木と、わざどうしのつながり・依存関係。学習指導要領と解説、研究成果に基づく。 |
| このプロンプト | 教科書会社の年間指導計画などから、単元のパラメータを抜き出して .sdkk を作る。 |

パラメータから決まるわざ（どの物語でも使うわざ、型や文種から出るわざ）はアプリが計算します。.sdkk には書きません。

## 使い方

1. 新しい会話に、次のものを添付し、下の「プロンプト」の枠の中をそのまま貼ります。
   - アプリのデータ：GitHub リポジトリの `data/core_data.json`（アプリの `index.html` でもかまいません）
   - 教科書会社の年間指導計画（内容解説資料）1〜6年
   - あれば：指導事項の配列表、教科書本文、前の版の .sdkk
2. 出てきた .sdkk を、アプリの「リストを書き出す／読み込む」で読み込みます。
3. 確認用CSVの「要確認」の行から順に、アプリの単元画面で文種・構成の型・展開の型・指導事項を確かめて直します。
4. 直し終えたら、アプリから .sdkk を書き出して残します。

## 取り扱いの注意

.sdkk には、教科書会社の年間指導計画の記述（ひも付けの根拠）がそのまま入ります。手元で使うためのファイルとして扱ってください。公開・配布する場合は、事前に教科書会社や関係団体に可否を確かめてください。

学校で作った年間指導計画から作る場合は、アプリの「リストを書き出す／読み込む」にある、CSVを作るためのプロンプトも使えます。

# 役割の分け方（確定済み。変えない）
- .sdkk は単元ごとのパラメータを持つ：時期・時数・指導事項（◎○）・言語活動例（☆）・文種・構成の型・展開の型・資料の記述に基づくひも付け。
- アプリはわざどうしの依存関係を持ち、パラメータからわざを展開する（前提依存・構成依存・文種依存・展開依存・指導事項からの展開）。
- このプロンプトは資料からパラメータを抜き出す。パラメータだけから決まるわざ（どの物語でも使うわざ、型や文種から出るわざ）は .sdkk に書かない。
- 教師は、出てきた .sdkk をアプリで読み込み、単元画面でパラメータを確かめて直す。迷うものは決めつけず、確度を下げて理由を書く。

# 入力
- 添付データ：core_data.json がアプリ本体のデータ。index.html を添付したときは、<script id="defaultData" type="application/json"> の中のJSONが同じもの（中の <\/ は </ に戻して読む）。使うのは次のもの。
  - sh：指導事項の表。sh.profile（版 ed・名前・コードの体系・学年→学年帯 band_of_grade）、sh.items（id＝学習指導要領コード16桁、grades、label 例「C(1)エ」「知技(1)オ」、text、activity＝言語活動例なら true、leaf）。
  - trees：ツリーごとの id（setsumei＝説明的な文章／bungaku＝文学的な文章）と対象の領域。
  - nodes：わざ。id, tree, parent, axis, kind, label_h, explain, stages（学年帯ごとの段階）, band, dep, mode。tree がないノードは、axis が k（ことばのわざ）か n（そうさのわざ）なら両方のツリーで共通、それ以外は setsumei。
  - 文種：ことばのわざの「文種」ノード（P_kind）の子。tree が setsumei（説明的な文章の文種）のものと bungaku（文学的な文章の文種）のものがある。id と label_h が文種の名前の対応になる。
  - unit_props：ツリーごとの、構成の型の選択肢（struct）、展開の型の選択肢（tenkai）、文種以外の単元の種類（extra_genres。例：詩）、文種から出す初期値（defaults）。
  - deps：指導事項 → 扱いうるわざ。ひも付けの判断の参考に読むだけ。
- 添付資料：教科書会社の年間指導計画（内容解説資料）1〜6年。指導事項の配列表、教科書本文があればそれも。根拠はこの資料だけ。記憶やウェブ（ほかの資料、授業例、作品の解説）を根拠にしない。
- 前の版の .sdkk があれば、比べるためだけに使う。値をそのまま写さない。前の版にある古い id は、データの meta.id_remap（古い id → 新しい id）で読み替えてから比べる。

# 手順
① 単元と教材の一覧
- 年間指導計画にある単元を、読むこと以外の領域も含めてすべて拾う。1つの単元に教材が複数あれば教材ごとに1件にする。
- 各件の項目：
  - id：t001 から資料の並び順に通し番号。
  - kind：「教科書」。publisher：会社名。edition：「令和○年度版」など資料の書き方。status：「要確認」。created_by：「prompt」。created_at：現在の日本時間（+09:00）。
  - grade（1〜6）、title（教材名）、unit（単元名。教材名と同じなら空文字）、vol（上・下など。なければ null）。
  - month（始まる月。1〜12）、month_to（終わる月。始まりと違うときだけ）、hours（資料の書き方のまま。例：「８時間（知・技②、読⑥）」）。
  - area：説明的な文章／文学的な文章／書くこと／話すこと・聞くこと。資料の領域・文章の種類の欄に従う。資料に書いていないときは文章の性質で判断し、報告に挙げる。
  - info（組になる資料・コラムなど）、write_unit（組になる書くことの単元）：資料にあれば書き、なければ空文字。
  - order：学年×100 ＋ 月の順×4 ＋（練習教材1／本教材2）。月の順は4月を1、3月を12とする。同じ値になるときは資料の並びで 0.5 ずつずらす。
- 分からない項目は空文字にして報告する。

② 指導事項と言語活動例
- items：その単元の指導事項を「◎コード」「○コード」で入れる。◎は資料で重点（主たる学習）とされたもの、○は扱うもの。資料に重点の区別がなければすべて ○ にして報告する。
- コードは sh.items から引く。資料の書き方（例：「読むことエ」「C(1)エ」「(1)エ」「知・技(1)オ」）を label の形にそろえ、その学年を grades に含み、activity でない項目の id を使う。1つに決まらないものは入れずに報告する。
- activities：言語活動例のコード（activity が true の項目の id）。資料に言語活動例の記載があるときだけ入れる。
- hairetsu：指導事項の配列表が添付されているときだけ。その単元の欄の印（◎・○・・・☆）を、印＋コードの形で配列表の並びのまま入れる。

③ 単元の性質（読むことの単元だけ）
- area から tree を決める（説明的な文章＝setsumei、文学的な文章＝bungaku）。
- genre_src：資料での文章の種類の呼び方（例：「説明文」「物語」「昔話」）。
- bunshu：P_kind の子のうち、tree がその単元の tree と同じものから1つ選び、その id を入れる。genre には選んだノードの label_h を入れる。文種のどれにも当たらず unit_props[tree].extra_genres にあるもの（例：詩）は、genre にその名前を入れ、bunshu は入れない。
- struct・tenkai：unit_props[tree].struct・tenkai の選択肢の文字列から、当てはまるものを配列で入れる。当てはまるものがなければ空配列（通常型）。まず unit_props[tree].defaults の文種の初期値を入れ、資料と本文の記述に照らして足し引きする。
- 判断の根拠は、資料と添付した本文の記述だけ。作品についての知識で型を決めない。本文がなく資料にも書いていない型は入れず、候補として報告に挙げる（教師がアプリで決める）。
- bunshu_note・prop_note：「確度：理由」の形で書く（例：「高：資料の単元名に『昔話』とある」）。確度は 高＝資料にそのまま書いてある／中＝資料・本文から読み取れる／低＝解釈が入る。
- 書くこと・話すこと・聞くことの単元には bunshu・struct・tenkai を入れない。

④ ひも付け（links。src「計画」）
- 読むことの単元ごとに、年間指導計画の「主な学習活動」「評価規準」「単元名」「題名」の記述から、その記述が指すわざのノードにひも付ける。ノードは、その単元の tree のものと、両方のツリーで共通のもの（axis が k・n）を使う。ノードの explain と、その学年帯（sh.profile.band_of_grade）の段階（stages）の説明に照らして判断する。
- links の各要素は {id, ev, src}。id はノードの id、ev は根拠にした記述を一字一句そのまま、src は「計画」。単元名なら「単元名「…」」、題名なら「題名「…」」の形にする。
- 読む前の動機づけや、子どもが自分の経験と比べる活動など、文章のわざを指さない記述ではひも付けない。
- 同じ単元の同じノードは1つにする（記述が複数あれば、いちばん直接に指す記述を ev にする）。
- 資料の記述によらず、パラメータだけから出るわざは書かない（アプリが計算する）。

⑤ ひも付け（src「本文」。教科書本文を添付した教材だけ）
- 本文の中に、そのわざが実際に使われている箇所を確かめたときだけ、src「本文」でひも付ける。「計画」と同じノードなら src を「本文」に書き換え、ev に確かめた内容を足す。
- ev には本文の位置（ページ・段落番号・場面）と確かめた内容を短く書く。本文は長く引かない。

⑥ そのほかの項目
- uses・focus：空配列にする（扱うわざ・重点のわざは教師がアプリで選ぶ）。
- src：その単元の根拠にした資料の名前。

⑦ ファイル全体
- {"schema":"sdkk-1","meta":{…},"texts":[…]} の形にする。
- meta：name（「会社名 版（手元用・公開しない）」）、note（どの資料に基づくか）、source（使った資料の名前の配列）、link_src（{"計画":"年間指導計画（主な学習活動・評価規準・単元名・題名）の記述に基づく","本文":"教科書本文で確認した（ev に本文の位置と確認した内容を書く）"}）、created_at（今日の日付）、ed（sh.profile.ed）。

# 確かめる（ひとつでも引っかかったらファイルを出さずに報告する）
- schema が sdkk-1。texts の id が重複していない。grade は1〜6、month・month_to は1〜12。
- items のコードは sh.items に実在し、その学年を grades に含み、activity でない。activities のコードは activity が true。印は ◎ か ○。
- bunshu は P_kind の子で、tree がその単元の tree と同じ。genre はその label_h か extra_genres のどれか。struct・tenkai の値は unit_props[tree] の選択肢のどれか。
- links の id は、その単元の tree のノードか、両方のツリーで共通のノード（axis が k・n）に実在し、ev が空でなく、src は「計画」か「本文」。同じ単元に同じノードが2つない。
- 同じ学年に同じ title が2つない（別の単元で同じ教材を使うときは unit で区別できること）。
